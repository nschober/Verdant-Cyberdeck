# Repository scope and publication inventory

The intended remote is **`verdant-cyberdeck`**, **private**, under the authenticated user's GitHub account. No username, remote URL or successful publication is asserted until GitHub confirms creation and the pushed commit is verified.

## Included

The complete current application source, five shell entry points, Python management/verification utilities, dependency notes, tests, synthetic fixtures, actual offscreen screenshots, usage/architecture/history documentation, original implementation as historical text, license, notices, policies, GitHub workflow/templates and reviewed verification evidence are part of the repository.

`docs/evidence/initial-*` preserves the reviewed original install/test evidence, including unsuccessful hardware checks. The initial README is retained as `docs/INSTALLATION-REPORT.md` so installation findings are not discarded during the rename. `docs/legacy/previous-app.py.txt` preserves the previous application source supplied on this host.

`docs/REPOSITORY-FILES.sha256` records the included source/document/assets checksums at preparation time, excluding itself to avoid a circular hash. `scripts/check_publication.py` checks tracked/staged files for common private-artifact types, private-key headers and selected credential formats. It is not a guarantee that all sensitive content is detected.

## Local-only material

| Material | Reason for keeping it local |
|---|---|
| `logs/installed-files.json` | Exact-content ownership/rollback state for this installation; restoring it elsewhere is unsafe |
| `logs/preserved-sha256.json` | Private host-specific Pwnagotchi configuration/unit evidence; preservation assertions do not transfer to another host |
| `logs/cyberdeck.log` and future runtime logs | May contain device, connection, tool and client details; only reviewed evidence copies are included |
| `logs/system-inspection.json` | Host-specific machine/driver identity; relevant hardware facts are documented without requiring a raw host dump |
| `backups/20261114-201426/` | Partial first backup of the same original launcher |
| `backups/20261114-201435/` | Original rollback copies, including the prior application and launchers; original application source is separately included as historical text |
| `backups/20261114-201830-*/` | Original launcher/autostart copies already represented by the installation report |
| `backups/github-preparation-*/` and later backups | Local pre-edit snapshots and rollback copies |
| `__pycache__/`, `.git/`, editor and environment files | Generated bytecode, local Git internals or machine settings rather than distributable source |
| Original `kali-cyberdeck-35.zip` | Complete initial local project backup; retained beside the renamed project, not blindly uploaded |
| Pwnagotchi files, keys, plugins, learned data and network settings | Owned by the external installation, never copied into this project or repository |
| Tool binaries, OS images, firmware and vendor assets | External dependencies with separate licenses; not redistributed |

No existing local backup is deleted. Keeping the repository private does not make it appropriate to store operational secrets. A source ZIP prepared from committed files contains the repository material above, not the full host-local rollback state. The original complete project ZIP is retained separately.

## Readiness checks

Before pushing, run software tests on an exported clean tree, shell/Python syntax checks, publication checks and a checksum review. Confirm that `logs/`, `backups/`, credentials and packet captures are not staged. Keep hardware gaps explicit. After connecting GitHub, create the private repository under the authenticated user, push `main`, confirm remote visibility and branch SHA, and inspect the first CI run before claiming GitHub CI passed.

If authentication is unavailable, the local Git repository, commit and ZIP remain ready; no remote creation or CI success should be claimed.
